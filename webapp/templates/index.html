System Architecture & Pipeline Methodology

PolyLID implements a hierarchical 5-stage inference pipeline designed to resolve code-switched token ambiguity across 65 languages and 12 writing scripts while minimizing computational overhead.

Stage 1

1. Text Tokenization & Script Tagging

Segments raw input into atomic word tokens and annotates each token with its Unicode script across 12 distinct script topologies (Latin, Cyrillic, Han, Arabic, Devanagari, Gurmukhi, Bengali, Gujarati, Tamil, Telugu, Thai, etc.).

Module: Tokenizer
Standard: Unicode UAX #29
Complexity: O(N) single-pass scan
Stage 2

2. Candidate Language Discovery

Performs global sentence-level and contiguous script-run evaluation to discover the active candidate set $D \subseteq L$, reducing search space from 65 languages down to 2–3 active languages ($20\times$ search space reduction).

Models: GlotLID + FastText + Lingua
Candidate Set: D = {l | P(l) >= theta}
Search Space: 65 -> |D| (2-3 typical)
Stage 3

3. Constrained Token Classification

Evaluates token-level probability distributions strictly projected over the candidate set $D$. GlotLID is excluded from token evaluation to maintain low inference latency.

Models: FastText + Lingua
Features: Subword & character n-grams
Latency: ~0.05 ms per token
Stage 4

4. Consensus Arbitration & Context Refinement

Resolves inter-model disagreements via consensus fusion. If confidence margin $M \le 0.25$, triggers bidirectional 3-token local window evaluation bounded by script invariants.

Modules: PredictionAnalyzer, ContextChecker
Decision: DecisionEngine (Voting / Margin)
Context Window: [-1, +1] bounded by script
Stage 5

5. Non-Destructive Smoothing & Span Assembly

Applies script-guarded non-destructive smoothing to filter isolated 1-token noise, merging adjacent identical predictions into contiguous spans.

Module: ResultRefiner
Invariant: Script boundaries preserved
Output: Span list with character offsets

1. Clean / Multi-Script Datasets

These datasets consist of standardized sentences crossing distinct Unicode script blocks (e.g., Arabic, Han vs. Latin). Because they lack severe social media noise, PolyLID's script-boundaries perform exceptionally well across both Token Accuracy and Exact Match.

Benchmark Dataset Language Pair / Topology Sentences (N) Token Accuracy Exact Match (EM) Partial Match (PM)

2. Noisy / Twitter Datasets (Mono-Script)

Code-Switching entirely within the Latin alphabet. Token Accuracy remains high (77%-94%), but uncleaned Twitter data (emojis, @usernames, slang) heavily drops Exact Match (EM). However, Partial Match (PM) proves the underlying detection engine remains robust (99%+).
