PolyLID Code-Mixed Dataset Access Registry
Datasets identified from Hidayatullah et al. (2022) systematic review
Purpose. This registry is intended to support a systematic cross-dataset evaluation of PolyLID. The review identifies 32 code-mixed datasets for language identification. The registry records the language combination, the review reference, the best verified public access route found, whether that route is a direct dataset download or a paper/resource page, and the expected compatibility with the frozen PolyLID evaluation inventory.
Important scope note. The primary PolyLID evaluation should use the frozen operational inventory discussed in the thesis. Datasets containing unsupported languages, or datasets whose core language material is Romanized/transliterated, are retained in this registry for coverage analysis but should not be silently folded into the primary benchmark.
1. Review basis
Hidayatullah et al. (2022), IEEE Access, DOI 10.1109/ACCESS.2022.3223703, [open review paper](https://doi.org/10.1109/ACCESS.2022.3223703) . The paper explicitly reports that it recognized 32 code-mixed datasets for LID and presents the dataset quality criteria used in its Table 10. The language-pair list below follows that 32-dataset set.

3. Recommended acquisition workflow
1. Download the dataset from the linked repository, attachment, or publisher/resource page.
2. Preserve the original files unchanged and record the exact version/date in the experiment log.
3. Inspect the annotation scheme before inference. PolyLID predicts language labels, while several review datasets additionally contain MIX, OTHER, NAME, LOCATION, UNKNOWN, or dialect-specific labels.
4. Normalize the dataset labels to PolyLID canonical ISO-style codes only where the mapping is unambiguous.
5. Run the full-coverage datasets under one fixed preprocessing protocol. Record tokenization, punctuation treatment, script handling, and sentence boundaries.
6. For partial/unsupported datasets, retain a coverage record rather than fabricating or silently dropping unsupported labels.
7. For Twitter datasets distributed via Tweet IDs, document whether the corpus was successfully reconstructed and report the retrievable subset size separately.

5. Acquisition risks and validation checks
• Historical Twitter resources can be distributed as tweet IDs rather than text. A benchmark should distinguish the original corpus size from the successfully reconstructed subset.
• Some datasets were created for broader code-mixed NLP tasks and include labels that are not directly language labels. A dedicated label-mapping step is required.
• The review is from 2022. Several datasets now have newer mirrors, versions, or successor resources. The link in this document is the best currently located access route, not a claim that it is byte-identical to the historical release.
• Romanized/transliterated datasets should be stored and documented, but they belong in a separate extension study because Romanization removes much of the script evidence used by the current PolyLID design.
